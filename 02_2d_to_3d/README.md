# 2차 업무 — Unit Test 구성 및 2D → 3D 변환

**달 사진 두 장으로 지형의 높낮이를 복원합니다.** 착륙 지점을 고르려면 어디가
평평한지 알아야 하는데, 사진에는 색만 있고 높낮이가 없습니다.

![달 지형 스테레오 복원 결과](outputs/00_overview.png)

```
사진 2장  →  시차 d  →  깊이 맵 Z = f·B/d  →  3D 포인트 클라우드
             ↑ 두 사진에서 밀린 픽셀 수      ↑ 그것을 3D 로 바꿉니다
```

| | 값 |
|---|---:|
| 대상 | 티코 크레이터 (높낮이 차 **5.376 km**) |
| 고도 오차 중앙값 | **0.0302 km** (기복의 0.56%) |
| 90 퍼센타일 | 0.0816 km |
| RMSE | 0.0828 km |
| 덮은 셀 | **76.1%** |
| 포인트 클라우드 | 311,550 점 |
| — 사진 한 쌍만 쓰면 | 0.0346 km · 62.7% |

여기서 **높낮이 차**는 그 지형에서 가장 높은 곳과 가장 낮은 곳의 차입니다.
오차가 큰지 작은지는 그 값과 견주어야 뜻이 생깁니다. 아래 본문에서는
지형학에서 쓰는 말 그대로 **기복**이라고 적습니다.

정답은 **LRO LOLA 레이저 고도계로 실제 측정된 고도**다. 근사로 만든 기준이
아닙니다. 시차 1픽셀이 0.45 km 를 바꾸는 촬영 조건에서
오차가 0.0302 km 이므로 **부화소까지 맞춘 셈**입니다.

**수렴각이 다른 네 쌍을 합쳐 얻은 값입니다.** 한 쌍만 쓰면 0.0346 km 에
62.7% 를 덮는데, 합치면 정확도와 덮는 범위가 **함께** 좋아집니다(7-7절).

**두 장은 달 광도함수와 센서 모델을 거쳐 만듭니다.** 시선 방향이 밝기에 들어가고
광자 잡음·광학 흐림·양자화가 얹힙니다(8절). 램버트 반사에 잡음 없이 돌리면 같은
설정에서 오차가 0.0359 km 로 나오는데, 그 숫자는 실제 영상에 옮겨 말할 수 없습니다.

**실제로 찍힌 사진으로도 확인했습니다.** 1971년 아폴로 15호가 필름에 찍은 두 장을
같은 파이프라인에 넣어 복원한 기복이 2.74 km 로, 같은 지역 LOLA 의
2.72 km 와 1.01 배 안에서 맞습니다(11절).

- 고도 모델: LRO LOLA 0.118 km/화소 (USGS Astrogeology, 공개 자료)
- 실제 사진: 아폴로 15호 매핑 카메라 AS15-M-1000 / 1001 (ASU 아폴로 영상 아카이브)
- 테스트: pytest **79개** 통과 (고도 모델이 없으면 3개 skip)

## 2. 촬영을 어떻게 세웠는가

궤도에서 찍은 원본 영상으로 곧장 스테레오를 돌리려면 카메라 자세 커널과 지도
투영을 다루는 전용 도구 체계가 필요합니다. 그 준비만으로 며칠이 갑니다. 대신
**이미 레이저로 측정된 고도 모델에서 출발**합니다.

고도를 3D 점으로 펴고, 자세를 아는 카메라 두 대로 다시 찍은 뒤, 그 두 장으로
고도를 복원해 원래 값과 비교합니다.

> **기하는 실제 달이고 영상은 렌더링입니다.** 밝기는 달 광도함수(Lunar-Lambert)
> 로 만들고 광자 잡음·광학 흐림·8비트 양자화를 거치므로 시선 방향과 잡음이
> 실제처럼 들어가지만, 실제로 찍은 사진은 아닙니다. 이 실험이 검증하는 것은
> **촬영 기하와 정합**입니다. 8절에 그 모델이 결과를 얼마나 바꾸는지 재 놓았습니다.

**두 카메라는 같은 지점을 바라봅니다(수렴 촬영).** 실제 궤도 스테레오도 나란히
두 대를 놓는 것이 아니라, 지나가며 앞뒤로 기울여 같은 지역을 두 번 찍습니다.

```
R1, t1 / R2, t2 = 두 촬영 지점의 자세
① 상대 자세   R = R2 · R1ᵀ,   t = t2 − R · t1
② 베이스라인  B = 2 · H · tan(수렴각 / 2)
③ 정렬·정합   stereoRectify(R, t) → StereoSGBM → 시차 d
④ 깊이        Z = f · B / d
⑤ 3D 좌표     X = (u−cx)·Z/f,  Y = (v−cy)·Z/f
```

| 기호 | 뜻 | 값 |
|---|---|---:|
| H | 촬영 고도 | 59.2 km |
| 수렴각 | 두 시선이 벌어진 각 | 15° |
| B | 베이스라인 | 15.6 km |
| f | 초점거리 | 500 px |
| — | 시차 1픽셀이 바꾸는 Z | 0.45 km |
| SNR | 최대 밝기에서의 신호 대 잡음비 | 100 |
| — | 태양 고도 | 25° |

**초점거리를 고도에서 유도합니다.** `f = H / 화소 크기`로 두면 영상 화소와 지형
화소가 1:1 이 됩니다. 고도를 상수로 박으면 고도 모델이 바뀔 때(합성 0.005 km,
LOLA 0.118 km) 시차가 화면을 넘거나 몇 픽셀로 쪼그라듭니다.

## 3. 결과

`outputs/00_overview.png` 에 왼쪽 영상부터 복원 깊이까지 한 줄로 있습니다.

| | 값 |
|---|---:|
| Z 오차 중앙값 | **0.0338 km** (시차 0.08 px) |
| RMSE | 0.0718 km |
| 시차 0.25 px (0.112 km) 이내 | **96.1%** |
| 시차 0.50 px (0.225 km) 이내 | 99.7% |
| 시차 1.00 px (0.45 km) 이내 | 100.0% |
| 값이 나온 픽셀 | 67.9% |

**허용오차를 km 로 못 박지 않고 시차 몇 픽셀인지로 잡았습니다.** 시차 1픽셀이
바꾸는 깊이가 이 촬영 기하의 분해능 한계이므로, 그보다 훨씬 작은 값을 기준으로
삼으면 알고리즘이 아니라 운을 재게 됩니다. 촬영 조건이 바뀌어도 뜻이 같다는
장점도 있습니다.

> 처음에는 0.005·0.01·0.02·0.05 km 를 썼다가 "0.02 km 이내 16.5%" 같은 값을 보고했습니다. 0.02 km 는
> 분해능의 1/22 이라 원리적으로 도달할 수 없는 기준인데, 성능이 나쁜 것처럼
> 읽힙니다. 지표는 장비의 한계에 맞춰야 합니다.

RMSE 가 0.0718 km 인데, 광도 잔차 관문을 걸기 전에는 0.1 km 였습니다. RMSE 는 크게
틀린 소수의 화소가 끌어올리는 값이므로, 그 화소들을 정답 없이 골라내 버리는
것만으로 크게 줍니다(9-3절). 중앙값과 함께 봐야 합니다.

## 4. 수렴각 — 정밀도와 덮는 범위가 맞바뀝니다

두 시선이 벌어진 각이 이 실험의 중심 파라미터입니다. 각이 크면 삼각형이 뚱뚱해져
거리가 정밀해지지만, 두 영상이 서로 달라 보여 같은 지점을 찾기 어려워집니다.

| 수렴각 | 베이스라인 | 시차 1px = Z | 값이 나온 픽셀 | Z 오차 중앙값 |
|---:|---:|---:|---:|---:|
| 10° | 10.4 km | 0.677 km | 76.6% | 0.0583 km |
| **15°** | **15.6 km** | **0.45 km** | **68.0%** | **0.0333 km** |
| 20° | 20.9 km | 0.336 km | 59.6% | 0.0361 km |
| 30° | 31.7 km | 0.221 km | 43.3% | 0.0279 km |

**10°에서 30°로 벌리면 오차가 0.0583 → 0.0279 km 로 줄지만,
값이 나온 픽셀이 76.6 → 43.3% 로 떨어집니다.** 한 쌍만 쓴다면
여기서 타협해야 합니다.

**그런데 타협하지 않아도 됩니다.** 각도마다 덮는 곳이 다르므로 여러 각도를 합치면
둘 다 얻습니다. 7-7절이 그 측정입니다.

`outputs/01_tradeoff.png` 의 왼쪽 그래프에서 두 선이 반대로 가는 것이 이것입니다.

## 6. Unit Test 설계

과제 예시의 테스트(p.14)는 출력 크기와 자료형만 확인합니다. 그것만으로는 수식이
틀려도 통과합니다. **손으로 답을 낼 수 있는 조건**을 만들어 숫자까지 대조했습니다.

| 갈래 | 예시 | 검증 방식 |
|---|---|---|
| **해석해** | 평지를 수직으로 보면 깊이 = 촬영 고도 | 1e-6 이내 |
| | 기울기 tan(t) 사면의 법선 | 1e-9 이내 |
| | 태양이 머리 위면 밝기 = albedo | 1e-9 이내 |
| **불변식** | `B = 2·H·tan(수렴각/2)` | 상대오차 1e-12 |
| | `p_j = R·p_i + t` 가 실제로 성립 | 1e-12 이내 |
| | B와 d를 함께 2배 하면 Z 불변 | 스케일 모호성 |
| **왕복** | 깊이 맵 → 3D → 고도가 원래 값과 같은가 | 0.002 km 이내 |
| **전체** | 렌더링→정렬→정합→깊이 를 한 번에 | 시차 0.5 px 이내 |
| **회귀** | 렌더링한 두 장이 `f·B/d` 에서 겹치는가 | 실제 결함을 잡은 테스트 |
| | 수직 시점 두 대가 오른쪽을 뒤집지 않는가 | 두 번째 결함 |
| | 지형이 카메라보다 높으면 멈추는가 | 세 번째 결함 |
| | 무늬가 없는 곳을 걸러내는가 | 네 번째 결함 |
| **경계** | 화소 크기 0, 수렴각 90°, 크기 불일치 | 예외 처리 |

**독립적인 경우는 `@pytest.mark.parametrize` 로 나눕니다.** 잘못된 수렴각 네 가지,
잘못된 화소 크기 두 가지가 그렇습니다. 한 번에 루프를 돌면 첫 실패에서 멈춰
나머지가 실행되지 않고 어느 값에서 깨졌는지도 이름에 안 남습니다.

## 7. 검토에서 찾아 고친 것

파이프라인을 다섯 갈래로 훑었다 — 기하 항등식, 수치 안정성, 데이터 흐름,
재현성, 교란 실험. **일곱 건이 나왔고 전부 고쳤습니다.**

> 이 절의 표들은 **8절의 촬영 모델을 넣기 전에** 잰 값입니다. 그때는 램버트
> 반사에 잡음이 없었으므로 절대값이 3절과 다릅니다. 각 항목이 무엇을 얼마나
> 바꿨는지를 보여 주는 기록이라 당시 값 그대로 둡니다.

### 7-1. 렌더링이 시차를 밀어내고 있었습니다

처음 실행에서 Z 오차가 **1.245 km** 나왔습니다. 분해능이 0.45 km/px 인데 2.8 px 이라
잡음치고는 크고, 무엇보다 **오차가 한쪽으로 치우쳐** 있었습니다(부호 있는 오차 평균
−1.101 km).

| 확인한 것 | 결과 |
|---|---|
| 정렬 창 보정이 두 카메라의 주점을 어긋내나 | 아님 — 같은 양만큼 옮긴다 |
| `Z = f·B/d` 가 실제 투영과 맞나 | **정확히 일치** |
| 정렬 좌표계에서 직접 렌더링하면 | **오프셋 0.0 px** → 기하와 기준 깊이는 옳다 |
| `alpha` 를 바꾸면 오프셋이 | 2.0 / 2.6 / 3.6 → **초점거리에 비례** (각도 0.3°) |
| 점 번짐(splat)을 끄면 | +2.6 → **+0.6 px** |
| 화소마다 광선을 쏘면 | **−0.10 px** |

원인은 렌더러였습니다. 점을 화소에 던져 그리면서 위치를 **반올림**하는데, 그 오차가
표면 기울기 방향으로 쏠립니다. 수렴 촬영의 두 카메라는 서로 반대로 기울어 있으므로
좌우가 반대로 쏠리고, 그 차이가 그대로 시차 치우침이 됩니다. 점 번짐은 깊이 버퍼에
3×3 최소값 필터를 거는 셈이라 표면을 카메라 쪽으로 당겨 이를 키웠습니다.

번짐은 **빈 화소를 메우는 데만** 쓰도록 바꾸고, 흩뿌리기 자체를 **화소마다
광선을 쏘아 지형과 만나는 점을 이중선형으로 찾는 방식**으로 교체했습니다.
**Z 오차 1.245 km → 0.066 km.**

### 7-2. 수직 시점 두 대의 오른쪽이 뒤집혔습니다

카메라 자세를 만들 때 "위쪽"을 수직(0,0,1)으로 뒀습니다. 아래를 내려다보는 카메라는
시선이 거의 −Z 라 그 기준과 나란해지고, 외적이 0 에 가까워져 영상의 오른쪽이
시선의 미세한 수평 성분으로 정해집니다. **두 카메라의 상대 회전이 15°가 아니라
180°로 나왔습니다.** 수평 기준(북쪽)을 주어 고쳤습니다.

### 7-3. 깊이 탐색 구간을 잘못 잡았습니다

`고도 ± 기복`으로 잡았는데, 정렬된 카메라는 수렴각의 절반만큼 기울어 있어
**지형이 넓으면 Z 가 화면을 가로질러 크게 변합니다.** 티코(75 km 폭)에서 Z 가
±5 km 흔들려 옳은 시차가 구간 밖으로 잘려 나갔습니다. 지형 경계 상자의 여덟
꼭짓점을 정렬 카메라로 옮겨 실제 Z 범위를 구하도록 고쳤습니다.

### 7-4. 광선이 수렴하지 않은 채 값을 내고 있었습니다

복원한 점이 실제로 고도장 위에 있는지 재 보니 화소의 **10%가 잔차 0.001 km 를 넘었고
최악은 0.3 km** 였습니다. 반복 횟수를 다섯 배로 늘려도 줄지 않았다 — 수렴이 느린
것이 아니라 **아예 수렴하지 않는 것**이었습니다. 지형 격자 밖으로 나간 광선이
가장자리 값으로 고정되어 진동합니다.

반복 뒤 t 를 한 번 더 갱신하고, **마지막 갱신 폭이 화소 크기의 1/100 을 넘으면
값을 내지 않습니다.** 잔차 최악 **0.3 km → 0.00004 km**, 0.001 km 초과 0%.

### 7-5. 무늬가 없는 곳에서 아무 값이나 내고 있었습니다

크게 틀린 화소(1 px 초과)의 평균 밝기가 **62** 로 전체 평균 **114** 보다 훨씬
어두웠다 — 크레이터 안쪽 그늘입니다. 국소 대비(7×7 표준편차) 하한을 재 봤습니다.

| 대비 하한 | 값이 나온 화소 | Z 오차 중앙값 | 1 px 초과 |
|---:|---:|---:|---:|
| 0 | 72.0% | 0.0661 km | 0.99% |
| **2** | **69.4%** | **0.0649 km** | **0.69%** |
| 4 | 63.0% | 0.0633 km | 0.75% |
| 8 | 47.2% | 0.0609 km | 0.94% |

하한 2 는 화소를 2.6 %p 만 내주고 **크게 틀린 화소를 3분의 1 줄입니다.**
`uniquenessRatio` 는 30 까지 올려도 지렛대가 되지 못했습니다(21 → 16.5%).

### 7-6. 시차가 정수 부근에 몰려 있었다 (픽셀 락킹)

시차 소수부를 세어 보니 정수 부근(±0.1 px)에 **49.3%** 가 몰려 있었습니다. 균일하면
20% 여야 합니다. SGBM 부화소 보간의 알려진 성질이고, 이것이 깊이를 **+0.043 px
(약 0.019 km)** 치우치게 만들었다 — 당시 전체 오차 0.065 km 의 3분의 1 입니다.

시차는 가로 방향이므로 **가로로만 늘려 정합한 뒤 되돌립니다.**

| 배율 | 값이 나온 화소 | Z 오차 중앙값 | 정수 부근 | 시차 편향 |
|---:|---:|---:|---:|---:|
| 1× | 69.4% | 0.0649 km | 49.3% | +0.043 px |
| **2×** | **69.3%** | **0.0346 km** | **35.9%** | **+0.024 px** |
| 4× | 69.6% | 0.043 km | 40.9% | +0.028 px |

**2배에서 오차가 거의 절반이 되고 화소 손실은 없습니다.** 4배는 오히려 나빠진다 —
보간이 없는 정보를 만들어 내지는 못합니다.

### 7-7. 여러 수렴각을 합치면 트레이드오프가 사라집니다

4절에서 "정밀도와 덮는 범위를 동시에 얻을 수 없다"고 적었는데, **한 쌍만 쓸
때의 이야기**였습니다. 각도가 다르면 정합에 성공하는 곳도 다릅니다. 정밀한 각도는
좁고 촘촘하게, 넓은 각도는 넓고 성기게 덮습니다.

각도마다 정렬 창의 크기가 달라 깊이 맵끼리는 화소 단위로 겹칠 수 없습니다. **지형
격자**가 모든 각도가 공유하는 유일한 좌표계이고, 만들려는 산출물 자체가 "격자
위의 고도"이므로 거기서 합칩니다. 가중치는 **1/분해능²** — 시차 1픽셀이 바꾸는
깊이가 그 각도의 정밀도이고, 오차가 거기 비례한다면 역분산 가중이 그 값이 됩니다.

| | 덮은 셀 | 오차 중앙값 | 90 퍼센타일 | RMSE |
|---|---:|---:|---:|---:|
| 10° 단독 | 70.9% | 0.0611 km | 0.143 km | 0.0993 km |
| 15° 단독 | 62.7% | 0.0346 km | 0.0923 km | 0.13 km |
| 20° 단독 | 54.5% | 0.038 km | 0.0856 km | 0.168 km |
| 30° 단독 | 39.1% | **0.0293 km** | 0.0718 km | 0.212 km |
| **네 각도 융합** | **76.1%** | **0.0302 km** | 0.0816 km | **0.0828 km** |

**어느 단독 각도보다 넓게 덮으면서, 30° 단독을 빼면 가장 정확합니다.** 30°는
0.0293 km 로 정확하지만 39.1% 밖에 못 덮습니다. RMSE 는 융합이 가장
좋다 — 크게 틀린 값이 걸러지기 때문입니다.

**각도끼리 어긋나는 셀을 버리는 것이 신뢰도 역할을 합니다.** 정답을 보지 않고
"믿을 수 없는 곳"을 가려낼 수 있는 단서입니다. 서로 다른 기하에서 본 값이 다르면
둘 중 하나 이상이 틀린 것입니다. 두 각도 이상이 값을 낸 셀이
66.0%, 세 각도 이상이 53.2% 다.

이 단서가 **실제로 오차를 예측하는지**는 오랫동안 확인하지 않은 채 쓰고 있었습니다.
9절에서 잽니다.

### 7-8. 다른 지역에서도 같은 결과가 나오는가

한 크레이터에 맞춰진 결과가 아닌지 확인하려고, 같은 설정 그대로 코페르니쿠스
크레이터(20.0°N, 3.6°W, 기복 5.659 km)에서 다시 돌렸습니다.

| | 티코 | 코페르니쿠스 |
|---|---:|---:|
| 기복 | 5.376 km | 5.659 km |
| Z 오차 중앙값 (한 쌍) | 0.0408 km | 0.058 km |
| 시차 단위 | 0.09 px | 0.13 px |
| 값이 나온 픽셀 | 70.5% | 61.1% |
| 융합 오차 중앙값 | 0.0376 km | 0.0445 km |
| 융합이 덮은 셀 | 76.6% | 63.0% |
| 영상에서 정해진 대비 하한 | 1.48 | 1.55 |

> 이 표는 두 곳 모두 **상수 알베도**로 돌린 값입니다. 실제 표면 무늬를 쓴 사진이
> 티코에만 있어서, 한쪽만 그것을 쓰면 지역끼리 견주는 뜻이 사라집니다. 그래서
> 3절의 머리 숫자(무늬를 쓴 값)보다 조금 나쁩니다.

**정확도는 같은 수준이고 덮는 범위가 다릅니다.** 코페르니쿠스는 위도 20°N 이라
태양 고도가 달라 그늘이 더 넓습니다. 파라미터를 다시 고르지 않고 그대로 돌린
결과다 — 대비 하한만 영상의 잡음을 보고 스스로 1.48 에서 1.55 로 옮겨 갔습니다(10절).

## 8. 촬영 모델 — 실제에 얼마나 가까운가

렌더링 영상으로 잰 성적을 실제 영상에 옮겨 말하려면, 렌더링이 실제와 어디서
다른지를 먼저 알아야 합니다. 두 가지를 넣었습니다.

**① 밝기에 시선 방향이 들어갑니다.** 램버트 반사는 밝기가 태양 방향에만
의존합니다. 그러면 같은 지면 조각이 두 사진에서 **정확히 같은 밝기**로 찍힙니다.
수렴각을 아무리 벌려도 밝기는 변하지 않으므로, 정합기는 실제로는 겪지 않을
쉬운 문제를 푸는 셈이 됩니다. 실제 달 표면은 후방산란이 강해 보는 방향에 따라
밝기가 달라집니다. 달 광도함수(Lunar-Lambert, McEwen)로 바꿨습니다.

```
I = A [ 2 L(g) mu0 / (mu0 + mu) + (1 - L(g)) mu0 ]

  mu0 = cos(입사각)    법선과 태양 방향의 사이각
  mu  = cos(방출각)    법선과 카메라 방향의 사이각   <- 여기서 시점이 들어옵니다
  g   = 위상각         태양 방향과 카메라 방향의 사이각
  L(g) = 1 + A1 g + A2 g^2 + A3 g^3      (도 단위)
```

L=0 이면 램버트, L=1 이면 Lommel-Seeliger 가 되는 보간식입니다. 티코에서 재 보면
두 시점의 밝기가 중앙값 1.5%, 90 퍼센타일 2.8% 만큼 달라집니다.

**② 센서를 거칩니다.** 광학 흐림(PSF) 0.7 px, 광자 잡음, 읽기 잡음,
8비트 양자화. 광자 잡음은 밝기의 제곱근에 비례하므로 **어두운 곳이 상대적으로
더 나쁘다** — 크레이터 그늘에서 정합이 어려운 물리적 이유입니다. 잡음을 밝기와
무관한 상수로 넣으면 그 사실이 실험에서 사라집니다.

| 촬영 모델 | 값이 나온 픽셀 | Z 오차 중앙값 |
|---|---:|---:|
| 램버트 · 상수 알베도 · 무잡음 | 67.7% | 0.0349 km |
| 달 반사 · 상수 알베도 · 무잡음 | 67.4% | 0.0346 km |
| 달 반사 · 실제 무늬 · 무잡음 | 67.5% | 0.0314 km |
| 달 반사 · 실제 무늬 · SNR 400 | 68.1% | 0.0331 km |
| **달 반사 · 실제 무늬 · SNR 100 (채택)** | **67.9%** | **0.0338 km** |
| 달 반사 · 실제 무늬 · SNR 40 | 66.5% | 0.0458 km |

**아래로 갈수록 실제 촬영에 가깝고 그만큼 성적이 나빠집니다.** 잡음이 지배적이다 —
반사 모델만 바꾸는 것은 0.000367 km 밖에 안 움직이지만, SNR 을 100 으로
내리면 0.00534 km 가 더해집니다. SNR 40 에서는 값이 나온 픽셀까지 무너집니다.

**아직 실제로 찍은 사진은 아닙니다.** 이 표가 말하는 것은 "렌더링의 어느 부분이
결과를 얼마나 좌우하는가" 이지 "실제 영상에서도 이만큼 나옵니다" 가 아닙니다.

## 9. 정답 없이 믿을 곳을 가려냅니다

실제 운용에는 정답 고도가 없습니다. 그러면 복원한 값 중 어디를 믿을지 두 영상만
보고 정해야 합니다. 정답을 쓰지 않는 신호를 여럿 넣고, **그것이 실제로 오차를
예측하는지**까지 쟀습니다.

### 9-1. 좌우 일관성 검사

왼쪽 기준으로 x 가 x−d 에 대응한다면, 오른쪽 기준으로도 x−d 가 x 를 도로
가리켜야 합니다. 한쪽에서만 보이는 곳(가림)에서는 이 왕복이 깨집니다. 매처는
대응이 없어도 반드시 무언가를 고르므로, 그 사실을 알려 주는 유일한 단서입니다.

| | 값이 나온 픽셀 | Z 오차 중앙값 | 90 퍼센타일 |
|---|---:|---:|---:|
| 좌우 일관성 없음 | 72.5% | 0.0353 km | 0.112 km |
| **좌우 일관성 적용** | **67.9%** | **0.0338 km** | **0.108 km** |

**효과가 작습니다.** 다른 관문을 이미 통과한 화소 중 1.7% 만 더 걸러 냅니다. SGBM 의
고유성 비율 검사와 얼룩 필터가 이미 상당 부분을 하고 있기 때문입니다. 90 퍼센타일이
0.1122 에서 0.1083 km 로 주는 것이 실질적인 이득입니다.

### 9-2. 그 신뢰도가 진짜 오차를 예측하는가 — 희소화 곡선

신뢰도가 낮은 순서로 화소를 버려 가며 남은 화소의 평균 오차를 그립니다. 같은 일을
**실제 오차 순서로** 하면 가장 빠르게 떨어지는 곡선(오라클)이 나옵니다. 두 곡선
사이의 넓이가 AUSE 이고, 작을수록 그 신뢰도가 오차를 잘 예측한다는 뜻입니다.

여기서 정답을 쓰는 것은 **채점할 때뿐**입니다. 신뢰도 자체는 정답 없이 계산됩니다.

| 신뢰도 | AUSE | 순위 상관 | 크게 틀린 것 AUC | 90% 버렸을 때 평균 오차 |
|---|---:|---:|---:|---:|
| **셋을 순위로 합침** | **0.263** | **+0.239** | 0.960 | 0.0631 → 0.0302 km |
| 봉우리 margin | 0.276 | +0.251 | 0.936 | 0.0631 → 0.0316 km |
| 봉우리 곡률 | 0.313 | +0.212 | 0.919 | 0.0631 → 0.0361 km |
| 광도 잔차 | 0.353 | +0.108 | 0.939 | 0.0631 → 0.0566 km |
| 각도 간 편차 (격자) | 0.457 | -0.067 | **0.971** | 0.0435 → 0.0427 km |
| 무작위 (대조군) | 0.609 | -0.001 | 0.501 | 0.0631 → 0.064 km |
| 국소 대비 | 0.931 | -0.154 | 0.255 | 0.0631 → 0.161 km |
| — 오라클 (실제 오차 순) | 0 | — | 1 | → 0.00303 km |

**전부 무작위보다 낫지만 오라클과는 멀습니다.** 오차의 크기를 맞추는 쪽(AUSE·순위
상관)에서는 **셋을 순위로 합친 신호가 가장 낫고(0.263 · +0.239)**, 단독으로는
봉우리 margin(0.276 · +0.251)입니다.

**두 열이 재는 것이 다릅니다.** 각도 간 편차는 크게 틀린 화소를 골라내는 데서
가장 높은 **AUC 0.971** 을 내지만 순위 상관은 -0.067 이라 오차의 크기는 전혀
못 맞춥니다. 광도 잔차도 같은 모양입니다(AUC 0.939, 순위 상관 +0.108). **큰 오류를
걸러내는 일과 남긴 값이 몇 미터인지 말하는 일은 같은 신호로 되지 않습니다.**

**국소 대비는 무작위보다 나쁩니다** — 대비가 높은 크레이터 테두리가 오히려 더
크게 틀리기 때문입니다. 대비를 신뢰도로 쓰면 안 된다는 뜻이고, 재 보기 전에는
몰랐습니다. 다만 정합 전 관문으로는 여전히 쓸모가 있습니다(7-5절) — 거기서는
크기가 아니라 무늬가 있는지를 봅니다.

## 10. 파라미터를 영상에서 정합니다

상수로 박은 값은 이 지형에서 훑어 고른 값입니다. 지형이나 촬영 조건이 바뀌면 다시
골라야 하는데, 그러면 자동으로 도는 파이프라인이 아닙니다. 5절의 블록 크기가 실제로
그렇게 뒤집혔습니다.

| 파라미터 | 예전 | 지금 |
|---|---|---|
| 시차 탐색 범위 | 지형 경계 상자에서 유도 | 그대로 (이미 옳았습니다) |
| 대비 하한 | 회색조 **2.0** 을 손으로 | **잡음 x 2** = 1.48 |
| 블록 크기 | 손으로 고른 상수 | 아래 참조 |

**대비 하한은 풀렸습니다.** 영상 한 장에서 잡음 표준편차를 추정하고(Immerkaer) 그
배수로 잡습니다. 티코에서 0.74 x 2 = 1.48 가 나오는데, 손으로 고른 2.0 과
거의 같으면서 **영상이 바뀌면 따라간다** — 코페르니쿠스에서는 1.55 가 됩니다.

**블록 크기는 절반만 풀렸습니다.** 광도 잔차와 좌우 일관성 통과율은 블록에 대해
단조라서 항상 양 끝을 고릅니다. 대신 **수렴각이 다른 두 촬영의 결과가 서로 얼마나
일치하는지**를 썼습니다. 정답을 전혀 쓰지 않으면서 복원의 정확도를 직접 겨눕니다.

|---:|---:|---:|---:|---:|---:|
| 3 | 64.2% | 2.23 | 0.0346 km | 0.308 | 0.0336 km |

| 7 | 64.8% | 2.27 | 0.0267 km | 0.346 | 0.0324 km |
| 9 | 65.3% | 2.28 | 0.0267 km | 0.343 | 0.0329 km |

**정답 없이 고르면 블록 21, 정답으로 고르면 11 입니다.** 맞았는지보다 잘못
골랐을 때 얼마를 더 내는지가 중요하다 — 0.00609 km,
15% 다.

**왜 어긋나는가.** 블록을 키우면 결과가 매끄러워지고, 그 매끄러움은 두 각도에
**똑같이** 일어납니다. 그래서 불일치는 계속 줄어드는데 실제 오차는 뭉개짐 때문에
늘기 시작합니다. 다만 블록 31 에서는 둘이 함께 무너지므로, 이 기준이 **완전한
실패는 잡아낸다**. 감쇠가 아니라 붕괴만 잡는 셈입니다.

## 11. 실제로 찍힌 사진으로 확인합니다

8~10절까지의 결과는 모두 **렌더링한 두 장**에서 나온 것입니다. 반사 모델과 센서를
실제 쪽으로 옮겨 놓았지만 사진 자체는 만든 것입니다. 그래서 실제로 찍힌 사진을
같은 파이프라인에 넣어 보았습니다.

### 11-1. 왜 아폴로인가

먼저 Kaguya 지형 카메라(TC1/TC2)를 시도했습니다. 앞뒤로 기울어진 두 대를 실은
스테레오 전용 카메라라 이 실험의 조건과 기하가 같습니다. 두 가지 걸림돌이 있었습니다.

| 받을 수 있는 형태 | 문제 |
|---|---|
| USGS 가 지도 투영한 COG | **전역 DEM 으로 이미 정사보정**되어 있다 — 고도에 따른 어긋남이 지워졌다 |
| DARTS 의 원본 (level 2B0) | 어긋남은 살아 있으나 **푸시브룸 카메라 모델**(SPICE/ISIS)이 있어야 고도로 바꿀 수 있다 |

첫 번째는 처리 기록에 그대로 적혀 있다 — `spiceinit ... shape=user
model=Lunar_LRO_LOLAKaguya_DEMmerge_Global_512ppd_radius.cub`. 실제로 재 보니
남은 어긋남과 LOLA 고도의 상관이 0.13 이었고, 맞춘 기울기가 촬영 기하가 예측한
값의 3분의 1이었습니다. `tools/check_real_pair.py` 가 이 확인을 다시 돌립니다.

두 번째는 카메라 모델 없이 특징점만으로 맞춰 보았으나 실패했다 — SIFT 특징점
8000개 중 통과한 것이 15개, 타일 위상 상관의 응답 중앙값이 0.057 이었습니다. 티코
안쪽 벽은 태양 고도가 8도라 그림자가 지배하고, 두 카메라가 반대쪽에서 보므로
한쪽에 보이는 사면이 다른 쪽에서는 그늘입니다.

**달 궤도 스테레오는 거의 전부 푸시브룸입니다.** 한 줄씩 쓸어 담으면서 자세가 계속
변하므로 두 장 사이를 행렬 하나로 적을 수 없습니다. 다른 푸시브룸 사진을 찾아도 같은
벽에 부딪힙니다.

**아폴로 매핑 카메라는 프레임 카메라입니다.** 한 순간에 한 장을 통째로 찍으므로 두 장
사이가 필수행렬 하나로 정확히 기술되고, 이 파이프라인의 정렬과 삼각측량이 그대로
성립합니다.

| | 값 |
|---|---:|

| 초점거리 | 76.054 mm = 2701 px |

**고도의 크기를 정답에서 가져오지 않습니다.** 초점거리는 카메라 검정값이고
베이스라인은 두 프레임의 중심 좌표에서 나옵니다. 둘 다 아카이브에 적힌 값입니다.

### 11-3. 스캔에 남은 왜곡을 사진만으로 걷어냅니다

처음 복원한 고도에 **중앙이 솟은 사발**이 있었습니다. 화면 중심으로부터의 거리
제곱과 상관이 0.77 이었는데, 실제 지형이 화면 중심을 기준으로 방사 대칭일 이유가
없으므로 그것은 지형이 아니라 왜곡입니다. 이 판본의 스캔이 필름 형식을 정확히 몇
화소에 담았는지 아카이브에 적혀 있지 않아서 생긴 것입니다.

계수를 **대응점만으로** 찾았습니다. "사발이 사라지는 값" 을 기준으로 훑습니다.
정답 고도는 쓰지 않습니다.

| | 사발 세기 | 필수행렬 내점 | 자세 차이 |
|---|---:|---:|---:|
| 왜곡 보정 없음 | 0.772 | 95% | 1.18° |
| **k1 = -0.0256** | **0.002** | **98%** | **0.20°** |

지금은 기복의 크기만 견줬고 화소 단위로 오차를 재지는 않았습니다. 한 쌍만 해 본
것이기도 합니다.

## 12. 한계

- **본 실험의 두 장은 여전히 렌더링입니다.** 밝기는 달 광도함수를 거치고 센서
  잡음까지 얹으며 표면 무늬는 실제 사진에서 가져오지만(8절), 두 장 자체는
  만든 것입니다. 실제로 찍힌 사진으로는 따로 확인했고(11절), **그쪽은 한 쌍만
  해 봤고 화소 단위 오차까지는 재지 못했습니다.**
- **신뢰도가 약합니다.** 정답 없이 계산되는 신호가 모두 무작위보다는 낫지만
  오라클과는 멀습니다(9-2절). 크게 틀린 화소를 골라내는 일은 잘하지만(AUC 0.971,
  각도 간 편차), 오차의 크기와는 가장 나은 신호(셋을 순위로 합침)조차 순위
  상관 +0.239 입니다. "여기는 몇 미터 안입니다" 를 화소 단위로 말할 수준이 아닙니다.
- **블록 크기를 정답 없이 못 고릅니다.** 교차 각도 불일치는 붕괴는 잡지만 완만한
  뭉개짐은 못 잡습니다. 정답으로 고른 값보다 15% 나쁜 값을 고릅니다(10절).
- **"대응이 없습니다"를 말할 수 없습니다.** 매처는 탐색 구간 안에서 반드시 무언가를
  고릅니다. 좌우 일관성 검사가 그 일부를 잡지만, 다른 관문을 통과한 화소 중
  1.7% 를 더 걸러 내는 데 그칩니다.
- **값이 나온 픽셀이 67.9% 다.** 나머지는 대부분 크레이터 안쪽 그늘로, 두
  사진에 같은 무늬가 보이지 않는 곳입니다. 광자 잡음이 어두운 곳에서 상대적으로
  크다는 점까지 넣었으므로, 이제 그늘의 어려움은 물리적으로 표현되어 있습니다.
- **가림(occlusion)을 다루지 않습니다.** 광선이 앞쪽 봉우리를 지나쳐 뒤쪽 지면에
  닿아도 그대로 받습니다. 시선이 지면에 거의 수직이라 지금 조건에서는 문제가
  없지만, 수렴각을 더 키우면 확인이 필요합니다.
- **고도 모델이 0.118 km/화소입니다.** 레이저 궤적을 격자로 편 것이라 매끈해서, 더 높은
  해상도 모델(LRO NAC DTM)보다 잔무늬가 적습니다.
- **촬영 자세를 정답으로 압니다.** 우리가 정한 값이라 오차가 없습니다. 실제 궤도
  영상이라면 자세도 추정해야 하고, 그 오차가 결과를 흔듭니다.

## 13. 개선점 — 아직 안 한 것

과제 요청내용 3번("변환된 3D 이미지의 시각적 결과를 분석하고 개선점을 도출")에
대한 답입니다.

**① 실제 사진을 지도 위에 놓고 화소 단위로 채점합니다.** 11절에서 실제로 찍힌 두
장으로 복원까지 했지만, 견준 것은 기복의 크기뿐입니다. 화소마다 오차를 재려면 복원
결과를 지도 좌표에 놓아야 하고 그러려면 촬영 자세 전체가 필요합니다. 한 쌍이 아니라
여러 쌍으로 늘리는 것도 남아 있습니다.

**② 신뢰도를 쓸 만한 수준으로 올립니다.** 지금 가장 나은 신호(셋을 순위로 합침)도
순위 상관 +0.239 에 그칩니다. 비용 곡선의 봉우리 모양이 표준적인 후보인데, OpenCV 의
StereoSGBM 이 비용 부피를 밖으로 내주지 않아 이긴 시차와 그 양옆 세 점에서 ZNCC 를
다시 재서 복원했습니다(`matching_margin`). 세 점으로는 봉우리를 거칠게밖에 못 잡습니다.
비용 부피를 그대로 내주는 매처로 바꾸거나, 여러 신호를 오차 크기에 대해 학습으로
맞추는 쪽이 다음 단계입니다.

**③ 픽셀 락킹을 더 줄입니다.** 가로 2배 업샘플로 정수 부근 쏠림을 49.3 → 35.9%
까지 낮췄지만 여전히 균일(20%)보다 높습니다. 4배는 오히려 나빠졌다 — 보간이 없는
정보를 만들지는 못합니다. 비용 곡선에 대칭 보간을 다시 얹거나 WLS 후처리를 쓰면
더 줄일 수 있다고 알려져 있는데, OpenCV 기본 배포에는 그 모듈이 없습니다.

**④ 더 높은 해상도 고도 모델을 씁니다.** LOLA 0.118 km 는 레이저 궤적을 격자로 편
것이라 매끈합니다. LRO NAC DTM(0.002~0.005 km/화소)을 쓰면 잔무늬가 많아져 정합이 쉬워질
것으로 보이지만, PDS 원본 포맷과 전용 도구 체계가 필요합니다. **남은 빈 곳
(23.4%)이 대부분 그늘이므로, 해상도보다 조명 조건이 다른 시점을 더 모으는
쪽이 먼저다** — 다만 그것은 실제 궤도 영상이 있어야 합니다.
